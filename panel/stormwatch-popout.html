When the connection is disrupted — why? (the protocol)

On a connectivity problem this walks the candidate causes in order and puts the evidence available right now beside each one. It surveys causes instead of assuming one, and it will say “cannot tell” rather than blame the sky when the telemetry does not support it. Your answer is recorded with the weather at that moment, so the answers accumulate into context.

What we have learned — answers accumulated

Settings — current value · default · valid range

Every threshold lives in stormwatch/config.json. The location is config, not code — change latitude/longitude and the whole heartbeat and protocol follow, with no code change. Values are validated against the range shown; an out-of-range value is refused and names the range.
