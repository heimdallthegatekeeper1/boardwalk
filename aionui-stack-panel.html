      4 · The guardrails — lanes & rules
      
    
        
    Two lanes own different parts of the codebase. Cross-lane edits are gated:
    
        
    
          
    KHAOSS lane
    
          
    ~/boardwalk/ · ~/aionui-stack-panel.html · panel_server.py — free to edit
    
          
    AGENTS lane

    §17 rule: HTML and CSS can be written via the bridge-write mechanism. JavaScript must go via terminal (Claude Code) — never bridge-write JS.
    
        
    LANE header: Every dispatch and report must include the LANE: field at the top (e.g. LANE: KHAOSS).
    
        
    Tab actions rule: Per-tab actions live inside tab content — never in the topbar or boardwalkTabBar. This is permanent.
    
        
    No in-run restarts: Do not restart AionUi or the main agent process mid-dispatch. The panel server itself can self-restart via POST /services/restart-panel.

      6 · Privacy — scrubbing, local-first, kill-after-use
      
    
        
    Local-first: All data stays on this-box unless explicitly shared. No data leaves the machine via the panel server itself.
    
        
    scrubber.py (~/boardwalk/scrubber.py): Regex-based PII scrubber. Catches API keys, passwords, emails, phone numbers, credit cards. Levels:
    
        
      
          
    • Level.RAW — no scrubbing (internal only)
      • 
          
    • Level.PRIVATE — scrub all PII (default for outbound)
      • 
          
    • Level.WORKSPACE — scrub for shared workspace use
      • 
          
    • Level.PUBLIC — scrub for public sharing
      • 
        
    
        
    example-a1 (LLM scrubber): Runs llama3.1:8b via Ollama for semantic PII detection. Used on the Signal bridge outbound path (kill-after-use — session is never resumed).
    
        
    Vault: The Obsidian vault at ~/vault/ has ring-level access control (ring 0–4). The vault watcher sanitizes new imports before they enter higher rings.
    
        
    RULE: Never send raw agent responses to external endpoints. Always scrub first.
    
      
    
    
    

    
    
    
      7 · Troubleshooting — common gotchas
      
    
        
    
          
    Mammouth 403
    
          
    Account budget cap hit. Check account spend at mammouth.ai → top up or wait for reset. Not a routing bug.
    
          
    Silent agent turns
    
          
    In AionUi, a "completed" turn with no output = upstream 4xx (budget or auth). Check the status line — it prints even on error.
    
          
    Gateway down
    
          
    Model-router on :8642 not responding → run hermes gateway run --replace to revive it.
    
          
    AionUi relaunch
    
          
    Teams have stale TeamMcpServer configs after relaunch. Emit team.ensure-session bridge event to repair. Ground truth: "registered N tool(s)" in the hermes log.
    
          
    Backend logs empty
    
          
    The debug panel polls on SSE tick (~3s). If still empty after 5s, check GET /logs?file=panel_server.log&lines=20 directly.
    
          
    Panel body won't open
    
          
    Check for display:none in the element's inline style — it overrides the CSS class toggle. Remove it if present (CSS handles hide/show via .cpanel-body.open).
    
          
    Token-drain scan
    
          
    See ~/boardwalk/reports/ for any token-drain scan reports. High usage usually means a runaway tool loop or a large context model on a simple task.
    
          
    example-a vs example-a1
    
          
    example-a = shared team leader (Mammouth, Opus 4.7). example-a1 = privacy scrubber (Ollama, llama3.1:8b). Different profiles — don't route work tasks to example-a1.

      ⓘ what's actually enforced (honest)
      
    
ENFORCING · remote-safe allowlist (default-deny). A remote (non-loopback) caller is admitted only to a fixed read/status allowlist; every other route returns 403 even with a valid token. Verified: /providers/set-key and /security/token return 403 to a token-bearing tailnet client; /api/health, /swarms return 200. Local (loopback) requests bypass the list and keep full access.

APPLIED · open / close from this card. The tailnet bind is now a one-click Open remote access / Close (above) — no terminal step. The exposure probe above is ground truth for what is bound right now.

FAIL-SAFE · the OFF switch only ever closes. It relaunches the panel on 127.0.0.1 (the exact revert). It is inert while already loopback-only.

DEVICE ≠ PERSON. Tailscale authenticates the phone as a device, not you as a person. An unlocked phone in someone else's hand is an open panel. The network layer does not solve this — an app-level gate on destructive actions does, and destructive actions are already loopback-only (never remote), which is that gate.

SHIPPED · phone login. A remote browser logs in at /login (paste the key, or scan the one-tap QR above); a panel_token cookie then carries auth on every request — navigations and SSE live-streams included. Credential/config/control routes stay 403 even when logged in.

    ⛈ Stormwatch — storms passing, and why the link dropped
    
  
    
    A storm heartbeat every 5 minutes over the site's coordinate — cloud density and near-term rain, from one
    keyless call — plus the connectivity protocol: when the link is disrupted it asks why
    (rain · clouds · satellite · Wi-Fi and more) with the live evidence beside each cause, and records the
    answer with the weather at that moment. The location is config, not code: change
    latitude/longitude in stormwatch/config.json and the whole protocol follows.
    “Could not look” is never shown as “clear”.
